# Foundation implementation plan

This standalone plan preserves the original product goals while describing the
actual Go boundaries. It is not permission to provision resources, infer
approvals, run models, or publish sensitive data.

## Product and architecture decisions

### Authenticated model choices and Antigravity CLI (0.3.42 source)

Both apps offer only fresh authenticated models from the chosen enrolled
computer, excluding unverified credentials, signed-out providers and stale
reports. Founder can request an agent-selected default through an ordinary
private message. Agents may deliberately change their own preferred defaults,
including prior Founder choices, with independent revisions and exact replay;
task/provider/model pins, mode, authority and work/retry fences remain intact.

The official standalone Antigravity CLI is a third provider through native ACP
stdio, with read-only authentication/model discovery, fixed tool-disabled text
and bounded nonprompting coding profiles. Versioned native assets require
independent GitHub digests and safe extraction; IDE launchers, arbitrary URLs,
GUI automation, native self-update adoption and credential copying are denied.
Health producers, heartbeat storage and fresh inspection preserve all ten
supported safe components, including environment failures.
Additive DTOs require a compatible source cutover, not SQL migration or automatic
publication/deployment. Fixtures and native help/admission probes are not paid
inference, authenticated-vendor or full-host production qualification.

### Per-agent app diagnostics and supervised native restart (0.3.41 source)

Both apps expose readable per-agent diagnostics at any time, including explicit
private saved snapshots when disconnected. Complete health/clocks/problems and
operation states replace generic field-count views. Founder-only fresh inspection,
exact proven closed-session recovery and runtime reset reuse durable proposal/
replay and server authority; other roles retain only self diagnostics.

A distinct signed native restart reaches a dead target identity/worker via the
independent Foundation root maintenance receiver and administrator-pinned worker
routes. It verifies fixed policy/source/generations, fresh nonce admission,
joined manager stop/shared slot and restarted services/current identity. Keys,
sign-in, state, journals, history, budgets and uncertain fences remain.
Only unchanged verified temporary pauses may restore prior AI; preexisting
manual/newer intent and independent pending-work/report/session fences win.
Lost responses/results reuse native receipts/outbox, not another restart.
Typed payload additions require a compatible coordinated release and explicit
native policy provisioning, not SQL migration or automatic deployment.

### Typed Foundation maintenance failure notices (0.3.40 source)

Foundation-origin blocked/refused maintenance notices include the existing
typed request-update source/state/result descriptor. This preserves the SQL5
maintenance-party guard instead of relaxing or rewriting immutable schema.
Previously a plain system-sender notice violated that guard and left an exact
native decline report pending. Isolated declined/deferred/failed regressions
require both notices, idempotent acknowledgement and unchanged manual mode.
No SQL/API/native payload change or retry/resumption authority is added;
0.3.39 clients/receivers remain protocol-compatible with the patch.

### Foundation-routed native upgrade preflight (0.3.39 source)

Founder `upgrade check/plan/status` supports exact minimal role/identity/platform
targets through the existing authenticated Foundation connection, without
per-target SSH or a cloud login. `--via-foundation` explicitly selects that
route for retained operator configurations. Independent preprovisioned native
receivers handle only typed inspect/challenge/status; ordinary worker ingress
cannot impersonate Foundation's root-private maintenance receiver or supply
helper/policy paths. The original signed install/start-lease and target-owned
GitHub verification/backup flow remains unchanged.

Durable private preflight controls use existing settings/reference receipts,
bind Founder device/target generations and a fixed 15-minute server lifetime,
and report explicit actual observations or failure. They are not ordinary
messages, task/provider calls, work slots, mode changes or install authority.
Plan2 journals retain exact operations/routes/control IDs and the same off-host
recovery key across uncertainty. Unsubmitted status reads dispatch nothing.
Receivers preserve pending observations, prioritize original maintenance outbox
delivery and exit for independent supervisor restart after activated source
changes. No native effect is repeated for receipt delivery.

Compatible binaries/policies/receivers require an authorized initial bootstrap;
old 0.3.36 installations cannot acquire a new control protocol from GitHub
metadata alone. Explicit operator plan1/offline recovery remains supported.
The new typed payload changes the locked fingerprint, not SQL or API/schema/
native version numbers. Source tests are not live service/OS qualification.

### Foundation-routed worker SSH onboarding (0.3.39 source)

Founder can opt into `agent add --via-foundation` when the new worker IP/SSH
port is reachable from Foundation rather than the Founder computer. Direct
remains the default, with no automatic fallback. The exact route is retained in
the existing local saga; old journals remain direct and route changes conflict.
Worker SSH stays end-to-end on Founder through a narrowly typed, Founder-only
native relay. The gateway still permits only API/join stdio, without forwarding,
new TCP listeners, server-side operator credentials or worker OS-account changes.
The internal raw proxy helper accepts only the original Founder's unfinished
retained operation. Its identity proxy pins the connection-local ticket to its
original owner transport across renewal and closes it after local disconnect.
All existing native-stage uncertainty, signed enrollment, exact release and
normal AI/work/spending gates remain. This is not reverse/NAT bootstrap.

The macOS 0.4.8 source exposes the explicit option only with a capable local CLI.
The new typed payload changes the locked native fingerprint; deploy compatible
server, CLI and identity proxies together under separate authorization. SQL and
API/schema/native version numbers remain unchanged. Deterministic authority,
chunk/bound/cancellation, real Unix-proxy renewal/disconnect and actual OpenSSH
host-pin regressions are source evidence, not native rollout qualification.

### Named native entity references (0.3.36 source)

macOS and iOS share readable `@ID`/`@{ID}` links with exact entity routing.
Legacy bare IDs also render as links in prose; code and technical JSON remain
literal. Entity names come from authorized reads, with message/comment/worklog
titles derived from their content and runs from summaries or kind/attempt.
Messages, discussion entries and runs have exact-record pages, independent of
list filters/pagination. Malformed routes cannot become executable actions.
The read-only `task run RUN`, native API and observer query add no schema,
claim, notification or work authority. Provider instructions mark human-facing
references but preserve structured IDs, CLI arguments and retained journals.
Source validation is separate from native upgrades, signing and deployment.

### Preferred models, useful Adhoc evidence and self-message prevention (0.3.35)

Founder can read/set agent provider/model defaults through the CLI and both
apps. Defaults have independent revisions and exact receipts, apply to new
invocations without changing mode/authority or local configuration, and yield
to task preferences. Bounded read-only Codex/Copilot catalogs permit a logged
provider-selected model when a preference cannot be used; provider/authentication
and uncertain-invocation fences remain.
New Adhoc plans carry team-safe meaningful titles, detailed descriptions and
criteria, with separate public reports and transactional lifecycle worklogs.
Private instructions/results remain private, legacy proposals replay unchanged,
and completion still needs independent verification. Ordinary self-message
sends are rejected server-side and in the apps without deleting history.
Additive native DTOs require compatible binaries but no SQL migration.
Deterministic local/native/app tests are source evidence, not live-provider,
physical-device or rollout qualification. A Jira-style task-board redesign is
not part of this source change.

### Bounded task reconciliation and conversation continuation (0.3.34)

Proven joined interruptions enter a distinct bounded recovery run under current
task readiness. Checked retained progress can permit same-task continuation;
unknown effects, unproved cleanup, changed source/authority/mode and exhausted
budgets remain fenced. One reconciliation per interrupted run and three per
specification bound automatic calls. Native never-invoked claims release only
unused reservations. Thread-only task resolution, requester/executor mode
separation, retained original-source guards and per-cycle reply operations
prevent replacement tasks, vague guard loops and duplicate effects after a lost
acknowledgement. Synthetic exact-size nested ZIP/XLSX and native process-join
tests verify actual output and conservative blocked states. Optional protobuf
fields are additive; no SQL migration, live task retry, publication or rollout
is implied by source acceptance.

The unreleased inspection refinement supplies controller-verified inspection
admission/budget and a paired CLI, requires native source-bound inspection
receipts and observed blockers, distinguishes expected new-output absence from
missing inputs, and keeps preparation's sandbox separate from later coding.
An exact authority-bound `recovery-review` permits one corrective review without
resetting spent counts or clearing execution uncertainty. Metadata-only refusals,
foreign receipts, changed files and unresolved effects remain fenced. This
refinement uses the existing native task-change/report shapes; no new native
payload fields or SQL migration are added. Opt-in real-provider synthetic
validation remains separate from default deterministic suites and deployment.

### Renewal-safe authority watches (0.3.33)

Validated owner renewal hands off only blocking update/event reads, preserving
the exact cursor and logical caller across old certificate expiry. The owner
generation and uninterrupted owner lifetime must match; no mutation, inference
or uncertain effect is replayed. Other calls retain normal drain/expiry rules.
Genuine loss of authority or transport remains a safety stop, reported as an
authority-channel interruption instead of a generic provider failure. Native
mTLS/Unix expiry regressions and mutation/revocation/caller-cancellation tests
cover the source behavior; isolated live-provider reproductions are separate
from default CI and do not qualify a deployed fleet.

### Native coding-tool configuration binding (0.3.31)

Coding children receive the already loaded exact worker configuration through
local `FDN_WORKER_CONFIG`, making bare worker CLI/service tools use their own
installation even when its configuration is not at the HOME default. Explicit
flags win; Foundation server commands ignore that worker context. Inherited
unrelated values are stripped and text-only calls receive none. No paths enter
provider prompts/argv/public DTOs, and no configuration/identity/state is
discovered, copied or moved. A real compiled-CLI child regression verifies the
native boundary rather than a fixture's direct API substitute.
Retained live provider evidence also showed a valid final reply rejected after
Codex's human diagnostic stream exceeded its cap. Managed Codex exec calls use
the capability-checked JSON event mode and still read the exact final-response
file. Actual output overflow remains failure; no log cap is raised or truncated
into success. Native-owner ping/revocation fixtures use real buffered Unix
sockets, retaining the unchanged production framing/admission deadlines.
The release's independent repeated Linux cleanup gate also exposed a native
PID-observation race: only proved disappearance of the exact old kernel group
can complete cleanup despite changed PID metadata. A live/replaced group or
permission/I/O failure remains fenced and is never adopted or signalled.

### Routine renewal and bounded inbox catch-up (0.3.30)

Owner-certificate renewal drains admitted native calls while new requests use
the renewed transport; expiry/revocation/owner loss still cancel immediately.
Settled tool-disabled failures before any reply application no longer globally
fence unrelated work. Only transient interruptions use a persistent per-source
budget of three total attempts with 5/10-second backoff, current authority and
pause checks. Exhausted/permanent sources retain evidence and protected help
without starving other messages/files. Genuine process uncertainty, coding
effects and possibly applied decisions keep exact recovery/retry requirements.
Tests cover the actual binary renewal failure and paused-file catch-up with
real verified private fixture bytes; these are not live-provider qualification.

### Logical sharing views after owned transport cancellation (0.3.29)

Expected cancellation/deadline errors from an owned byte-stream teardown leave
the authorized logical viewer reconnectable at its original expiry. They do
not become a failed session merely because the surrounding supervisor is still
running. Explicit closure, current authority, revocation, protected surfaces and
native cleanup/input fences remain independently enforced.

### Native terminal long state paths (0.3.28)

tmux creation, observation, passive attachment and owned cleanup use a relative
socket address from the same private parent when an absolute address exceeds
the platform Unix limit. Canonical socket/ownership records and user state stay
unchanged; explicit pane working-directory selection preserves approved
workspace behavior. Real long-path regressions check native output, kernel
ownership and cleanup. Existing unproven launch evidence is not erased or
declared safe by this change; native rollout qualification remains separate.

### Verified native maintenance receipt reconciliation (0.3.27)

The independent request receiver recognizes the exact signed permit's already
verified native receipt while completing its original queued request. It records
the normal target decision/result lifecycle without repeating service stops,
backups, installation or native start admission. A changed permit remains a
conflict. This supports an explicitly authorized coordinated strict-protocol
cutover; it does not retry unknown/prepared work, renew expiry, change mode or
grant new OS authority. Native rollout qualification remains separate from
source fixtures and must be recorded from actual observed outcomes.

### Unified selected-resource sharing source work (0.3.26)

SQL11 adds private target-owned terminal inventory/selection. Founder opens
logical terminal/VNC views during execution by role; delegates require explicit
server-fixed approvals of at most 24 hours, reusable only until original expiry.
Target/Founder selection updates the same view without renewing it. All bytes
cross Foundation's authenticated native relay; no peer routing is introduced.
Execution output uses owner-only bounded live logs and managed read-only tmux
mirrors, without converting batch providers into interactive inference.
Linked input leases require a Founder request and task-safe target acknowledgement
under the existing work slot and cleanup fences. Protected credential UI remains
human Founder-only. RFB filtering, target-owned VNCAuth, CLI/observation/mobile and
shared app controls are source implementations, not live OS/backend/provider,
secret-isolation, security or fleet qualification. Real native prerequisites and
any skipped/blocked qualification must be reported separately.

### Web pages and scoped website sign-in source work (0.3.25)

The existing-tools workflow also covers actual web-page inspection, ordinary
navigation/search/filter/pagination and authorized authenticated pages. Known-
password ordinary website sign-in or reuse of an agent-owned session is allowed
under exact current site/account authority, with credentials read only by a local
non-logging routine and sanitized content returned to the model. Password
possession alone grants no account/disclosure authority. Verify the authenticated
account/page rather than a form submission or HTTP status, and never blindly
repeat rejected, challenged or uncertain login effects. Foundation/provider
authentication, MFA/CAPTCHA, protected SSO/consent and human sessions keep their
existing boundaries. This adds no credential store, managed browser, native/schema
change or live website/credential-isolation qualification.

### Browser/file investigation with existing tools source work (0.3.24)

Ordinary Founder/delegate messages, relevant task comments and approved tasks
can request browser downloads and questions about PPTX/DOCX/PDF/photos. Tool-
disabled planning preserves the source, questions and required browser method
in a source-bound action; actual inspection uses the existing claimed work slot.
Copilot coding permits page retrieval with `web_fetch`, not browser automation.
Agents use available local browser/parser/image tools, verify downloaded bytes,
cite content locations, distinguish text from visual evidence and report missing
tools or unsupported content instead of guessing from metadata/receipts.
Follow-up questions reuse verified local copies and the exact thread context.
No managed browser/Office runtime, implicit installation, new controller,
automatic URL fetch, schema/protocol/authority change or live-browser/model
qualification is implied. Private files are never automatically sent to external
converters or exposed through shared task records.

### Human help and normal local access source work (0.3.22)

Typed protected help-message actions open an exact unexpired scope from desktop
and foreground iOS. Existing active grants are reused; a missing grant requires
explicit Founder review/authorization before opening. Server-side session
creation rejects expired/resolved notices and changed parties/provider/project/
task/screen scope. Phone terminal bytes use a binary-only app-private bridge;
VNC uses trusted bundled assets, ephemeral loopback browser state and existing
pinned SSH/mTLS relay. No credential UI enters JSON, transcripts or clipboard.
Foreground teardown closes owned sessions without changing automation mode.
Current task status stays at the top level across tabs/scrolling in both apps.
Approved coding calls use normal installing-user filesystem/command/component
access without a redundant workspace opt-in; explicit disabled bindings,
task/mode/uncertainty/OS/financial authority remain. Text-only controller calls
remain tool-disabled. Source/build fixtures are not a live rollout or physical
phone/provider sign-in/privacy qualification.

### Shared capacity and environment source work (0.3.17)

Startup capacity discovery and environment reporting use one native collector
and the existing private inventory. Onboarding receives detailed stable system
facts alongside its original observations/hash. Native and embedded reports
project that snapshot and refresh only live memory/storage usage, runtime and
Foundation executable details; embedded initialization performs no desktop
tool/network discovery or subprocesses. Legacy inventories are enriched
transactionally without changing historical review hashes, unknown counts,
identity, knowledge, journals or exact-operation evidence. Explicit inventory
refresh creates a new review basis; periodic telemetry does not invoke AI or
rewrite it. Live usage exceeding a retained total blocks reporting pending an
explicit refresh. Public environment DTOs, the locked native payload contract,
API/native versions and SQL8/localSQL1 remain unchanged. This is local source/
fixture work, not a live deployment or provider/fleet qualification.

### Monitoring and scoped announcements source work (0.3.16)

Both apps display current reported computer OS/CPU/memory/storage and Foundation
executable details with independent device/key binding, installed versus running
source and server-timed stale/missing states. Native workers and foreground
mobile hosts publish safe observations without private paths, provider probes
or new slots/controllers.
Founder/current delegates preview exact global/project broadcast audiences and
send notices, autonomous action requests or upgrade intents. Each recipient has
an ordinary private durable thread and exact replay; authority changes fence
source-bound actions. Existing nondestructive permissions remain usable without
per-message signoff. Destructive changes/new costs require case-by-case Founder
approval; software replacement retains exact signed native upgrade authority.
API/native versions and SQL8/localSQL1 remain; additive DTO ledger/fingerprint
changes require compatible binaries. Publication/live rollout are separate.

### Founder desktop onboarding source work (0.3.15)

The macOS app adds a Founder-only Add agent form and fresh sign-in requests,
plus a protected native PTY/tmux terminal and an embedded ephemeral VNC browser.
`agent add` performs explicit fresh-worker SSH bootstrap using the existing OS
account, independently confirmed host pin and exact published server release.
Only signed public enrollment material crosses machines; installation,
registration, connected native services and provider authentication stay
distinct. `agent add-status` and `assistance status` inspect retained outcomes
without retrying uncertain native work, creating sessions or starting login.
There is no server/root installer, live-state adoption, Founder-device
enrollment, new controller, inference authority or schema/protocol change.
Local fixtures and a development bundle do not qualify live SSH, provider,
desktop/VNC, native reboot or distribution behavior.

### Response-by-default source work (0.3.14)

Fresh ordinary CLI/API messages and desktop/mobile human replies request a
response unless explicitly disabled. Existing AI-mode text replies use the
recipient's provider/model and serial controller; manual mode and independent
authentication/safety/spending gates remain unchanged. AI replies can request
subsequent replies; at 100 round trips Founder receives one informational
warning, not an interruption or cutoff. The controller loads relevant original/
recent thread and task context and handles later messages independently.
Assigned/mentioned task comments use exact generation-bound attention.

Further retrieval/actions use durable source-bound plans and self-assigned
Adhoc records under narrow standing readiness, then the existing tool-enabled
claimed execution path. Applicable skills/context and actual checks are
referenced in the source reply only after the real report is acknowledged.
Private requests/results are not copied into shared task records. There is no
new controller/slot, blind inference/action retry, SQL migration or native
payload field/type. Existing stored messages, drafts, proposals, mode, OS,
spending, verification and uncertainty fences remain. Publication/deployment
are separate from source/fixture acceptance.

### Foreground mobile source work (0.3.13)

The `mobile` facade/C bridge embeds bounded CLI reads/manual dispatch and the
identity service's owner/renewal/proxy into an app-linked foreground host.
Pinned in-process SSH replaces only the mobile subprocess boundary; mTLS,
purpose/owner generations, protobuf and proxy method/path restrictions remain.
An app-private capability attachment avoids sandbox Unix-socket path limits,
without claiming kernel peer credentials for an in-process channel. Desktop
native entrypoints retain their kernel-checked sockets and OpenSSH subprocess.

There is no second controller, work slot, provider inference, native receiver,
desktop-health overwrite, background daemon, Mac relay or copied key. Swift
uses the same core manual policy, threads and exact proposal/replay store.
The native development app and compile/fixture/simulator evidence do not imply
physical-device enrollment, signing, production or App Store qualification.

### Desktop observation source work (0.3.12)

The local desktop wrapper adds private historical message/thread pagination and
one read-only `agent-cli observe` stdio session. It reuses bounded, authorized
private/shared feeds with entity selectors and current-watermark snapshots.
SQL8 appends query indexes without changing shipped SQL1-SQL7 or business data.
Ordinary business changes invalidate only matching subscribed reads; remaining
local/health sampling is inside the observer and active-interest-only.
Read-only `discussion show ENTRY` and observer `entry` reads resolve original
comment ancestors outside loaded pages; worklogs remain distinct records.
There is no UI polling loop, new controller/owner, direct UI database access,
HTTP listener, inference or automatic mutation retry implied. Existing human
writes retain their operation IDs, revisions and uncertain-outcome evidence.
Live enrollment, source-bound release and physical mobile qualification remain
separate gates.

- One computer per non-Founder identity and one active work slot per agent.
  Founder may enroll independent keyed computers and retain multiple live
  connections under the same actor; this never creates additional work slots. The
  existing installing OS user owns identity keys, provider state and runner work;
  identity and runner processes share its UID/HOME without new users/groups.
- Every non-Founder is autonomous/unattended; only Founder coordinates human
  needs and explicitly pauses/resumes global mode. Delegates may be AI agents.
- Persistent scoped Founder-issued assistance authorization survives restarts
  and live-connection expiry; targets need no human or repeated consent.
- One authoritative binary TLS message service and embedded SQLite; agents never write the
  server database directly. Service-controlled policy applies to every client.
- Pinned SSH forced stdio (`fdn-api`/`fdn-join`) into local Unix ingress plus
  inner mTLS; no API TCP listener, bearer bootstrap or token-only runtime.
- A dedicated Foundation SSH account/UID per enrolled computer, including each Founder device;
  kernel peer UID must agree with certificate instance/agent/key/owner epochs.
- Founder-only signed public registration; private software keys stay in the
  installing user's private identity state, never provider prompts/shared records.
  Process separation is lifecycle organization, not same-user key isolation.
- Confirmed different simultaneous non-Founder owner keys plus a fresh incumbent binary control
  ping ban the entire identity, including the original. Founder is exempt from
  duplicate-owner auto-ban, not account/certificate/generation checks. Stale/dead
  reconnects, ordinary CLI traffic, collisions and unproved attempts do not ban.
- Recovery is explicit with fresh keys/generations; Founder recovery is only
  root-local private Unix maintenance, not an agent gateway capability.
- Software-first account/key isolation, not physical clone prevention: full
  software/RAM clones and sequential use remain possible. Native hardware
  signing is optional future work; no adapter or attestation is implemented.
- Founder/project delegation controls assignment and current readiness/result
  approval; local tool permission and financial/legal authority stay separate.
- Human and automatic launches use one controller/prompt and identical fences.
- Agent-owned local memory, skills and knowledge precede shared publication.
- Deliberately published company/project/agent Markdown notes carry shared
  instructions, missions/goals, skills and references. Founder/current scoped
  authority/self control edits; every new task call receives the applicable
  snapshot without publishing private memory or automatically fetching resources.
- Clarification is productive question/answer/specification refinement, followed
  by exact-current signoff. Questions can also pause active work safely.
- Keep three snapshots per mutable source, never hidden unbounded history in
  receipts. Source/audit/event/run retention is a separate future policy.
- Private material stays local. Deliberately published future files/diaries/
  skills/ideas are team-readable; no promised per-file read isolation.
- Current targets: native Linux Foundation, Linux/macOS ARM64 agents; release
  binaries for Linux amd64/arm64 and macOS arm64.

## Read-only worker health and stuck-work diagnostics

Operational execution coordination is message-first: private typed requests,
recipient-owned acceptance/refusal/defer reasons, linked non-forcing follow-ups
and actual result replies. Work still uses existing approved task execution;
exact native upgrades use independent policy-bound request receivers, including
a deterministic Foundation handler. Central safety/authority records remain
immediate. Source fixtures do not imply receiver provisioning, protocol rollout
or a live upgraded request workflow.

The supported inspection leaves are `agent-cli agent diagnose AGENT_ID` and
`agent-cli message diagnose MESSAGE_ID`, using typed authenticated read-only
endpoints. General agent diagnosis is Founder/self; message diagnosis remains
strictly party-private. Local work/service status includes a timestamped `health`
snapshot, with effective provider/model versus configured reply preference,
phase/deadline and separate liveness/progress clocks. Missing/stale/unknown data
and non-authentication blockers remain visible, including after sign-in.

Workers optionally piggyback version-1 observations on existing 30-second
heartbeats; old bodies and the `Agent` response remain compatible. Bounded
service-owned latest-report/incident settings need no new migration (API/schema
2, server SQL 5, local SQL 1). The non-AI server watchdog monitors missing
heartbeat/report (90 seconds), deadline plus grace (30 seconds) and eligible
unexplained queued replies (120 seconds), including manual Founder. It does not
classify pause/no-response-requested/idle/in-deadline work as stuck. Protected
scoped alert/recovery messages persist and dedupe independently of 15-minute
sign-in notices; none of this starts login/session/inference/retry/resume/recovery.
Native/outside monitoring is still required for a Foundation outage.

CLI/guidance acceptance is limited to the focused source checks documented in
[TEST_PLAN.md](TEST_PLAN.md#diagnostics-cli-and-guidance-acceptance). Server/worker
regressions are separate, and no live Agent1, deployment, inference or release
qualification is implied.

## Founder on-demand inspection and exact closed-session recovery

The source adds `agent diagnose AGENT --refresh` and
`agent repair AGENT --input FILE`, with one common
`agent operation REQUEST_ID` state/result lookup. Unflagged diagnosis remains
saved read-only GET, and `agent recover` remains identity recovery. Founder-only
version-1 controls bind requester/target generations and immutable 900-second
expiry; protected server-only messages/results cannot be forged through ordinary
message send/receipt and do not become model prompts. Queued/checking/offline or
expired controls are not fresh success. Operation lifespan is separate from
provider/sign-in-notice/live-session deadlines. Dynamic `server_observed_at` and
server-anchored result `captured_at` distinguish server capture/expiry from target
inspection/provider/health UTC observations; skew cannot renew control authority.
The dynamic server projection is excluded from immutable fingerprints.

The dedicated non-inference worker loop performs bounded safe refresh checks
while paused/fenced/busy. Provider observation remains separate from in-flight
health; credentials present but unverified do not prove usability, and ready is
observed rather than inference-tested. Exact recovery requires the current
server-confirmed terminal session/fence SHA256, current generations, shared
`work.lock` and pre-existing durable native `CleanupProven` evidence, with atomic
local mutation/receipt and exact result replay after network uncertainty.

Old/unproven fences without native ownership return `operator-required`; native operator action
may still be needed for retained Agent1 state. No name/PID absence proof,
arbitrary process stop, journal/inference retry, pause bypass, identity recovery,
evidence erasure, session open, sign-in renewal, native restart or new spending/
task authority is provided. Already-approved ai work may resume only when all
independent fences permit; inspect operation then diagnostics for actual progress.
CLI/proxy/guidance fixture checks are separate from server/worker acceptance and
from live Agent1, native deployment, release or vendor qualification. No deployment
or version bump is part of this source-only work.

## Autonomous target-owned interactive recovery

Founder-only `agent reset AGENT_ID --input FILE` now adds an explicit
identity-preserving runtime control, including Founder self-reset. It cancels
and joins the daemon's owned controller/session work, retries owned cleanup and
reinitializes its in-process supervisor/scheduling. It keeps mode, identity,
authentication, notes, workspaces, history, journals/outbox and retry authority.
Recognized terminal legacy tmux endpoints now receive bounded target-native
cleanup under reset's joined slot: exact private socket/inode, kernel peer/start/
group and pane-parent checks, native stopped proof and preserved retired inode

alone do not strand reset. Independent uncertainty, replaced endpoints,
unavailable kernel inspection and genuinely unprovable resources still remain
operator-required; automatic cleanup and exact repair do not gain this scope.
The existing protected operation protocol supplies fixed expiry/generations and
exact result replay; a started interrupted reset never cancels newer work again.
This is not native service restart, factory reset, deployment or provider login.
The reason-only native payload and all SQL/protocol versions stay unchanged.

Routine session cleanup now precedes operator escalation. The manager retries
the exact endpoint it opened with bounded native calls and 1-30-second backoff;
failed closes are retryable, and proved no-process tmux preparation failures
retire their own fences. New tmux ownership records bind target/session/fence
generation, private socket, UID, process group and kernel process start identity.
Closing or server-confirmed terminal attempts can recover after a daemon restart
without adopting another process or launching login again.

Cleanup proof uses exact fingerprint comparison; retirement and its private
local receipt are atomic. Existing local-safety updates wake eligible ai work
without mode/approval/budget/retry changes or inference replay. The server
suppresses human session-fence alerts for a 30-second server-timed recovery
grace, so transient cleanup does not interrupt Founder. Authentication and
other essential blockers keep their existing separate rules.

Legacy missing ownership, an incomplete launch identity, unavailable authority,
active sessions, busy/uncertain work and unprovable cleanup remain explicit
stops. No source fixture proves live Agent1 recovery or deployment. Local SQL1,
server SQL7, API/schema2, native protocol2 and the locked payload schema are
unchanged by these local ownership records.

### Target architecture and scope

- Use persistent, bidirectional SSH stdio streams as the communication backbone.
  Replace internal HTTP/JSON and WebSocket exchanges with bounded, typed protobuf
  messages; do not introduce gRPC, an HTTP replacement framework, or a broker.
- `agent-cli` and `agent-service` attach through peer-checked local Unix IPC to
  the separate `agent-identity` service. That service owns keys and upstream
  connections; CLI attachment never creates another identity owner.
- Foundation derives the connecting principal from the fixed gateway's kernel
  peer UID and registered account. Never accept a claimed UID/AgentID as proof.
  OS permissions govern account/socket admission; Foundation transactions still
  enforce project, task, private-party, approval, mode and generation authority.
- Commands/results, explicit queries/snapshots, scoped updates, cancellation,
  checkpoints and keepalives share a small application message protocol.
  Request/reply behavior does not require a general RPC framework.
- One logical agent session may use separate purpose-bound SSH streams.
  Owner liveness and cancellation must not wait behind desktop/bulk bytes or
  inference. Do not assume the current native SSH adapter multiplexes all
  traffic onto one physical SSH connection.
- Cover ordinary business traffic, local IPC, activation/owner control, private
  maintenance, account provisioning and remote relay transport. Browser-facing
  viewer HTTP/WebSocket and external vendor/download protocols are separate
  edges, not internal coordination transports.
- Keep SQLite, existing domain policy and retained JSON persistence/evidence.
  This is not a database replacement, general replication system, new automation
  switch, shell-command-per-action design, or authority to deploy.

### S1: establish OS-backed admission without weakening current security

Preserve dedicated Foundation accounts/UID reservations, pinned SSH, fixed
gateway commands, no arbitrary shell/PTY/forwarding, protected Unix socket

Define how an admitted SSH transport is bound to the approved key generation,
instance, purpose and owner session. A UID, client-claimed generation, or lookup
of the registry's latest generation alone is insufficient. Prove that a
previously authenticated SSH transport cannot open newly accepted channels after
revocation/fresh-key recovery. Removing an authorized key or locking an account

### S2-S3: implement the narrow protocol and preserve logical operations

Use a bounded length-prefixed protobuf envelope with explicit protocol
negotiation and typed command/result/query/update/control variants. Keep
connection-scoped correlation IDs distinct from durable operation IDs and update
cursors. Pin generation tooling and verify generated-source reproducibility.

Define field presence for edits, numeric/enum validation and unknown-field/version
policy. Reject unsupported or privileged message kinds explicitly. Bound frame
allocation, decoded collections, queues, in-flight requests and stalled writes;
test truncation, malformed lengths, disconnects and cancellation. Multiple local
CLI clients must not collide or interfere with the service's pending requests.

Reuse [domain contracts](internal/domain/) and [transactional policy](internal/foundation/).
Do not implement policy only in a generated client or accept mutable server-owned
fields through a general-purpose payload. Keep private owner/signing/control
operations inaccessible to runner IPC; no generic privileged invocation method.

Preserve existing logical action/request fingerprints, receipts and errors.
Protobuf bytes must not become a new fingerprint that invalidates retained
operations. Test cross-transport replay, including lost acknowledgements and
same-operation/different-input conflicts. Translate retained local HTTP
method/path/body proposals and outbox records into their exact known typed
operations without rewriting the original evidence or invoking a model again.

Keep current databases, identities, knowledge, journals, fences and configuration
bindings. Add ordered server migrations only for new durable structures; do not
rewrite shipped schemas. Prefer existing local durability structures; if a new
format/schema is necessary, version and compatibility-test it explicitly.

### S4: make durable, relevant updates the normal discovery path

Append change records in the same transaction as accepted business mutations;
notify in-memory subscribers only after commit. Rollbacks and exact operation
replays must not create phantom or duplicate business changes. Waiting sessions
must not hold SQL transactions/connections or query on each keepalive tick.

Cover task/specification/assignment/result changes, project authority, discussion
and attention generations, private messages/read/disposition, sessions/grants,
mode/revocation and protected agent operations. Notify both former and current
affected assignees/delegates/owners where authority changes. Do not broadcast
private IDs/payloads through the existing team-visible event feed.

Bind subscriptions/cursors to authenticated scope and security generations.
Define consistent snapshot/high-watermark and race-free catch-up/subscription.
After reconnect, replay from the durable checkpoint; unavailable history requires
an explicit bounded resynchronization, not silent cursor reset. Recheck current
authority before disclosure. Define retention separately; never prune recovery
evidence merely to simplify a feed.

Coalesce relevant updates by resource/category without losing the durable
pending-work indication. Bound slow-consumer queues and disconnect/resynchronize
explicitly rather than silently dropping required changes. Keep expiry,
retry/backoff, deferred work and watchdog deadlines on bounded timers; not every
time-based transition has an incoming mutation to wake it.

### S5: replace polling without changing worker or CLI authority

Replace the one-second shared-event/urgent-inbox, 500 ms session-discovery and
five-second agent-operation discovery loops with the shared scoped update path.
Remove repeated full selection scans, unchanged cursor writes and unchanged
urgent-head wakeups. Atomically persist the cursor with pending local work
before advancing the checkpoint; on restart, reconsider retained pending work.

Keep update reception, control handling and health publication responsive while
paused, fenced or busy. Ordinary work still uses the same serial controller,
work lock, priority/fairness, approval gates and prepared report/outbox path.
Initial synchronization, explicit queries and recovery reconciliation remain
observable operations, not concealed fast polling loops.

Retain heartbeat/health semantics separately from transport keepalives: liveness
is not progress. Cached diagnostics remain read-only; explicit refresh/repair
retain protected operations, fixed expiry, server-clock capture bounds and exact
cleanup/fence proofs. Delivery never automatically marks a message read.

Preserve existing CLI commands, JSON/error/exit shapes, explicit read actions,
watch NDJSON/checkpoints and one-page behavior. Keep provider prompts, private
knowledge and tool-disabled/coding boundaries independent of wire encoding.

Retain active-run authority guards until pushed task/project/mode/ownership
changes and disconnect/expiry handling prove equivalent cancellation. Remove
